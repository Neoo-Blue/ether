### Plex Home per-directory incident — owner `thr_cgtbun5tzc`

Implementation: `8f5453d5e` (`incident/home-per-directory`). Single-directory
Home requests partition library namespaces and playlists by source and put
mixed curated rows on the first pinned source; the Home layout remains in
control, non-Continue rows use shelf style, and Continue Watching selects the
requested libraries and checks the Home inclusion policy. Legacy no-directory
and comma-list Home requests retain the existing assembly. Jellyfin/Emby
personal Home obtains a single neutral snapshot and deduplicates personal
shelves by row ID (`internal/frontends/mediabrowser/personal_home.go`); Silo
obtains a single Home request (`internal/frontends/silo/browse.go`), so neither
uses Plex's stacked per-directory protocol.

Sibling promoted requests share a viewer/client-scoped candidate snapshot and
visibility decisions; current viewer authorization and Home layout are still
applied on each response. Snapshots expire after 10 seconds or a repeat of a
directory, and are bounded to eight entries, 1 MiB of candidate hubs and 2,048
visibility decisions per entry; oversized candidate sets are not retained.
Discarded directories use layout facts without rendering full Plex metadata.

Counts are from separate warmed copies of the supplied production snapshot;
detached catalogue refreshes retain request trace context, so these counts
include work attributed to the originating request even when it continues in
the background. The deep trace attributes the largest remaining hydration to
loading episodes for watched-show leaf badges. `EXPLAIN QUERY PLAN` for those

exact page it can still fall back to a catalogue-wide sort; the no-library-scan
requirement therefore remains **open** for that worst case. Removing the
fallback without an exact precomputed index would silently alter or omit the
row. Home-load caching is also intentionally bypassed for clients with no
client identifier or oversized candidate sets.
